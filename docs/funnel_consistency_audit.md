## 1. Raw database counts by `event_type`

```sql
SELECT event_type, COUNT(*) AS event_count,
       COUNT(DISTINCT payload->>'external_track_id')
         FILTER (WHERE payload->>'external_track_id' IS NOT NULL
                   AND payload->>'external_track_id' != '') AS distinct_tracks
FROM events
WHERE store_id = '00000000-0000-0000-0000-000000000101'
```

## 3. Funnel aggregation query

Repository loads all zone-enter + purchase events in period (no `session_id` gate):

```python
# app/repositories/funnel_repository.py
select(Event).where(
    Event.store_id == store_id,
    Event.occurred_at >= from_ts,
    Event.occurred_at <= to_ts,
    or_(
        Event.event_type == "vision.zone.entered",
        Event.event_type == "analytics.purchase.completed",
    ),
)
```

Service resolves visitor key:

1. Session path: `track:{external_track_id}` from `VisitSession`
2. Event-only path: `track:{payload.external_track_id}` when `session_id` is NULL

Stage mapping via `DEFAULT_ZONE_TYPE_MAPPING` (`entry_threshold`, `promo_island`, `consultation` included).

Calculator applies **first-touch dedupe** per stage per visitor key.

| Issue | Effect |
|-------|--------|
| `session_id IS NOT NULL` on funnel events | 143/146 zone enters excluded |
| Missing zone mappings | `promo_island`, `consultation`, `entry_threshold` ignored |

## Why funnel < unique visitors (22)

Not a bug. Definitions differ:

- **Unique visitors (22):** any detected track across all cameras
- **ENTRY (2):** tracks crossing entry line only
- **ZONE_VISIT (14):** tracks entering floor zones
- **BILLING (5):** tracks reaching checkout/queue

20 tracks never crossed entry_threshold but appear on floor cameras.
